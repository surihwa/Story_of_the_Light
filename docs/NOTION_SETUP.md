# 노션 연결하기

처음 한 번만 하면 되는 작업입니다. 20분쯤 걸립니다.

## 1. 통합(Integration) 만들기

1. <https://www.notion.so/my-integrations> 접속 → **New integration**
2. 이름은 아무거나(예: `Story of the Light`), 워크스페이스를 고릅니다.
3. Capabilities는 **Read content**만 켜면 충분합니다.
4. 발급된 **Internal Integration Secret**을 복사합니다. → `NOTION_TOKEN`

## 2. 데이터베이스 네 개 만들기

Profile · Story · Logs, 그리고 연표.
속성 이름은 아래 표대로 **한 글자도 다르지 않게** 맞춰 주세요. 코드가 이름으로 찾습니다.

### 공통

모든 콘텐츠 DB에 `탭`(다중 선택)이 필요합니다. 옵션은 아홉 개입니다.

```
OC    서리화 · 카르네아데스 · 로레트 모린 · 이스노티 헤멜
Pair  상서고 · 로렌티 · 이브리화 · 흑와단
World 세계
```

대분류(OC / Pair / World)는 노션에 넣지 않습니다. 중분류만 고르면 사이트가 알아서 묶어 줍니다.

이름이 긴 셋은 **성 없이 `로레트` `이스노티` `야슈톨라`로 적어도 인식됩니다.** 별칭으로 등록돼 있어서, 이미 짧은 이름으로 입력해 두셨다면 그대로 두셔도 됩니다. 화면에는 언제나 풀네임이 나옵니다.

한 행에 여러 탭을 골라도 됩니다. 그러면 여러 탭에 함께 나타납니다. 아무것도 안 고르면 `세계` 탭에만 뜹니다.

### Profile

| 속성 | 형식 | 비고 |
|---|---|---|
| `캐릭터` | **제목** | `서리화` `카르네아데스` `로레트 모린` `이스노티 헤멜` `야슈톨라 룰` `그레틴` `이벨린` `흑와단` 중 하나. `src/config/characters.ts`의 키(또는 별칭)와 같아야 색이 붙습니다 |
| `번호` | 숫자 | 작은 번호가 위로 |
| `탭` | 다중 선택 | |

### Story

| 속성 | 형식 | 비고 |
|---|---|---|
| `제목` | **제목** | |
| `번호` | 숫자 | 1화, 2화… 순서대로 |
| `탭` | 다중 선택 | |
| `날짜` | 날짜 | 비워도 됩니다 |

### Logs

| 속성 | 형식 | 비고 |
|---|---|---|
| (제목 속성) | **제목** | 이름은 아무거나. **비워 둡니다.** 사이트에서 안 씁니다 |
| `번호` | **ID** | 새 행을 만들면 자동으로 붙습니다 |
| `탭` | 다중 선택 | |


**ID 속성 만드는 법**: 표 헤더의 `+` → 속성 유형에서 **ID**(고유 ID) 선택 → 접두사에 `LOG` 처럼 적으면 사이트에도 `LOG-12`로 표시됩니다. 비워 두면 숫자만 나옵니다. 기존 행에도 자동으로 일괄 부여됩니다.

ID 속성을 쓰면 사이트에서 **번호가 큰 것부터**, 즉 가장 나중에 추가한 행이 맨 위에 뜹니다. 숫자 속성을 쓰는 Profile·Story는 반대로 작은 번호부터 나옵니다. 별도 설정 없이 속성 유형만 보고 결정됩니다.

Logs는 제목 없이 **본문만** 카드에 보여 줍니다. 10줄까지는 그대로 나오고, 넘어가면 잘린 뒤 눌러서 전문을 봅니다. 그러니 본문에 바로 쓰시면 됩니다.

### 연표

| 속성 | 형식 | 예시 |
|---|---|---|
| `내용` | **제목** | `서리화가 빛의 축복을 받다.` |
| `시기` | 선택 | `-10년` `-1년` `신생` `창천` `홍련` `칠흑` `효월` `황금` `백은` |
| `관련 캐릭터` | 다중 선택 | `서리화`, `야슈톨라` |
| `순서` | 숫자 | (선택) 같은 시기 안에서의 순서 |

`시기`에 숫자를 쓰면 신생 이전 구간으로, 확장팩 이름을 쓰면 그 이후 구간으로 자동 정렬됩니다.

## 3. 통합을 DB마다 초대하기

각 DB 페이지 오른쪽 위 **···** → **Connections** → 1단계에서 만든 통합을 선택합니다.
**네 개 전부** 해 줘야 합니다. 이걸 빼먹으면 그 DB만 조용히 비어 나옵니다. 가장 흔한 실수예요.

## 4. DB ID 찾기

DB를 전체 페이지로 연 뒤 주소창을 봅니다.

```
https://www.notion.so/워크스페이스/1a2b3c4d5e6f7890abcdef1234567890?v=...
                                  └──────── 이 32자리가 DB ID ────────┘
```

`?v=` 앞까지가 DB ID입니다. 하이픈은 있어도 없어도 됩니다.

## 5. 로컬에 넣기

```bash
cp .env.example .env
```

```env
NOTION_TOKEN=secret_...
NOTION_PROFILE_DB=...
NOTION_STORY_DB=...
NOTION_LOGS_DB=...
NOTION_TIMELINE_DB=...
```

```bash
npm run build
```

콘솔에 카테고리별 건수가 찍히면 성공입니다.

```
[content] profile: 6건
[content] story: 12건
[content] logs: 48건
```

아직 안 만든 DB는 비워 두면 됩니다. 그 카테고리만 빈 화면으로 나오고 나머지는 정상 동작합니다.

## 6. 깃허브에 올릴 때 — 토큰은 코드에 넣지 않습니다

토큰과 DB ID는 저장소에 **절대 들어가지 않습니다.** 두 곳에 나눠 둡니다.

| | 어디에 | 커밋되나 |
|---|---|---|
| 내 컴퓨터 | `.env` | 아니요 (`.gitignore`에 있음) |
| 깃허브 액션 | 저장소 Secrets | 아니요 (암호화 저장, 로그에도 `***`로 가려짐) |

`.env.example`은 변수 **이름만** 적힌 빈 껍데기라 커밋해도 됩니다.

### 시크릿 등록하기

저장소 → **Settings** → 왼쪽 **Secrets and variables** → **Actions** → **New repository secret**

다섯 개를 하나씩 추가합니다. 이름은 아래와 정확히 같아야 합니다.

| Name | Secret |
|---|---|
| `NOTION_TOKEN` | `secret_` 으로 시작하는 통합 시크릿 |
| `NOTION_PROFILE_DB` | Profile DB의 32자리 ID |
| `NOTION_STORY_DB` | Story DB ID |
| `NOTION_LOGS_DB` | Logs DB ID |
| `NOTION_TIMELINE_DB` | 연표 DB ID |

등록한 값은 나중에 다시 열어 볼 수 없습니다. 바꿀 수만 있으니, 노션 통합 페이지에서 언제든 다시 복사할 수 있다는 점만 기억하면 됩니다.

### 빠뜨렸을 때

시크릿 이름을 하나라도 잘못 적으면 **빌드는 성공하는데 샘플 데이터가 배포되는** 사고가 납니다. 그래서 두 겹으로 막아 뒀습니다.

- 워크플로의 **Check secrets** 단계가 비어 있는 이름을 찾아 즉시 실패시킵니다.
- 그걸 통과하더라도, 빌드 코드가 CI에서 자격 증명을 못 찾으면 에러를 던집니다.

일부러 샘플 데이터로 배포해 보고 싶다면 build 단계에 `ALLOW_SAMPLE_CONTENT: 'true'`를 추가하면 됩니다.

아직 안 만든 DB가 있다면, 그 시크릿 이름을 `Check secrets` 단계의 목록과 `build` 단계의 `env`에서 지우면 그 카테고리만 빈 화면으로 나오고 나머지는 정상 배포됩니다.

### 실수로 토큰을 커밋했다면

깃 히스토리에서 지우는 것보다 **노션에서 토큰을 폐기하고 새로 발급하는 편이 확실합니다.**
<https://www.notion.so/my-integrations> → 해당 통합 → Secrets → **Refresh**. 새 값을 시크릿에 다시 넣으면 끝입니다.

## 빌드가 실패할 때

깃허브 액션 로그에서 **빨간 X가 붙은 단계를 펼쳐** 마지막 부분을 보세요. 요약 화면의 `Process completed with exit code 1` 한 줄만으로는 원인을 알 수 없습니다.

| 단계에 찍힌 내용 | 원인 |
|---|---|
| `등록되지 않은 시크릿: ...` | 그 이름의 시크릿을 아직 등록하지 않았습니다 |
| `노션 자격 증명을 찾지 못했습니다` | 시크릿 이름 철자가 다릅니다 |
| `[profile] DB 를 읽지 못했습니다` 등 | 메시지에 적힌 안내를 따르세요. 통합 초대를 빼먹은 경우가 가장 많습니다 |
| `[blocks] 아직 다루지 않는 노션 블록` | 실패는 아니고 경고입니다. 그 블록만 본문에서 빠집니다 |

DB 오류는 네 개를 한꺼번에 검사해서 **문제가 있는 DB 를 전부 모아** 보여 줍니다. 하나씩 고쳐 가며 다시 빌드하지 않아도 됩니다.

### Node.js 20 지원 종료 안내가 보입니다

`actions/checkout@v4` 같은 액션이 Node 20 을 쓴다는 **경고**입니다. 빌드가 실패한 원인이 아니며, 깃허브가 알아서 최신 런타임으로 돌려 줍니다. 신경 쓰이면 워크플로의 `@v4` 를 `@v5` 로 올리면 됩니다.

## 잘 안 될 때

**`[content] 노션 설정이 없어 샘플 데이터로 렌더링합니다.`**
`.env`가 프로젝트 루트에 있는지, 변수 이름 철자가 맞는지 확인하세요.

**특정 카테고리만 0건**
그 DB에 3단계(Connections 초대)를 안 했을 가능성이 큽니다.

**글은 뜨는데 엉뚱한 탭에 있음**
노션 `탭` 옵션 이름과 `tabs.ts`의 `label`이 다릅니다. 공백까지 똑같아야 합니다.

**Profile 배지가 회색으로만 나옴**
`캐릭터` 값이 `characters.ts`의 키와 다릅니다. 매칭 실패 시 회색으로 대체됩니다.

**본문 이미지가 안 보임**
노션 파일 URL은 약 1시간 뒤 만료되기 때문에, 빌드할 때 `public/notion-assets/`로 내려받아 두고 빌드가 끝난 뒤 `dist/`로 옮깁니다(`integrations/notion-assets.mjs`). 로그에 `[images] 내려받지 못해…` 경고가 있으면 그 URL이 원인입니다.

**GitHub Pages에서 CSS가 깨짐**
`astro.config.mjs`의 `base`가 저장소 이름과 다릅니다.
